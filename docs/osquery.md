# osquery pack

Meiscope reads the certificates your osquery estate already reports. It does
not install an agent and does not run queries on hosts.

## Privacy

Only certificate metadata and file metadata are collected:

- `certificates` table columns: names, issuer, validity, key algorithm and
  size, key identifiers, SHA-1 fingerprint, serial, and the store or path.
  No certificate bodies and no private keys (the table has none).
- Keystore files (`*.jks`, `*.p12`, `*.pfx`, `*.pem`, `*.kdb`): path, size,
  modification time, owner id, permission mode and SHA-256 only. File
  contents are never read into results and never leave the host.
- Never collected: private-key bytes, keystore passwords, key-alias secrets.
  The collector never opens a keystore, and never guesses, defaults or
  brute-forces a password.

### Keystore containers

`.p12`, `.pfx`, `.jks` and `.kdb` files are keystore containers, usually
password-protected.
Because the pack does not open them, each one is reported, never skipped
silently, with the finding `keystore_not_parsed` (carrying the file path
and size, plus the store type, owner, mode and digest). A `.pem` file is a
plain text bundle and carries no finding. Custody is reported as
`key_custody: unknown` for certificates: osquery 5.x has no private-key
presence column.

## Limits (decision D3)

| Setting | Default | Hard ceiling |
|---|---|---|
| `keystore_max_bytes` (per file) | 10 MiB | 100 MiB |
| `keystore_max_files` (per host and run) | 1,000 | 10,000 |

Both are per scan scope: set them in the adapter configuration
(`"settings": {"keystore_max_bytes": "52428800"}`) and generate the matching
pack with `meiscope-collector adapter pack --max-file-bytes N --max-files N`
(or `--format fleet`). Values above the ceilings are rejected when the
configuration loads, with an error that names the setting and the ceiling.
Raising the ceilings themselves needs a product decision.

System trust-store directories (read by the certificates query already) and
container data directories (`/var/lib/docker`, `/var/lib/containerd`,
`/var/lib/containers`, kubelet pods, Docker and containerd under
`C:\ProgramData`) are excluded: there is no container root-filesystem
scanning.

Every run reports `skipped_oversize`, `skipped_excluded` and `skipped_limit`
(and `skipped_feature_disabled`) in the run result, the log line `adapter run`
and the totals line `adapter run totals` (heartbeat fields). Because osquery
drops those files inside the query, two cheap counting queries
(`meiscope_keystore_counts_*`, no hashing) report how many files each rule
left out.

## Files

| File | Use |
|---|---|
| `packs/osquery/meiscope.conf` | osquery pack (standalone `osqueryd`, Kolide, any TLS/remote config). Platform-scoped: `posix` and `windows` queries |
| `packs/osquery/fleet-queries.yml` | the same queries as Fleet saved queries (`fleetctl apply -f`) |

Both are generated by `meiscope-collector adapter pack` for the default
limits, and a test fails when they drift. Queries: `meiscope_certificates_posix`,
`meiscope_certificates_windows` (including per-user stores, with `sid`,
`username`, `store_location`), `meiscope_keystores_posix`,
`meiscope_keystore_counts_posix`, and for each Windows root
`meiscope_keystores_windows_<root>` and `meiscope_keystore_counts_windows_<root>`
(see below). List them with `adapter pack --list`. All are snapshot queries with a 24 h
interval. Note that osqueryd starts its scheduler counter at the current Unix
time, so a query with a 86400 s interval first runs at about 00:00 UTC
(plus splay), not at start-up.

## What is covered on Windows

On Windows: every certificate in the certificate stores, plus certificate and keystore files in common application folders and any folders you add.

Certificate stores are read by `meiscope_certificates_windows` (every store, including per-user stores). Files are searched only in these folders, down to 4 folder levels below each one; there is no whole-drive, whole-Program-Files or whole-ProgramData walk, because osquery lists a whole directory tree before it filters it:

| Root id | Folder |
|---|---|
| `inetpub` | `C:\inetpub` |
| `java_security` | `C:\Program Files\Java\*\lib\security` |
| `adoptium_security` | `C:\Program Files\Eclipse Adoptium\*\lib\security` |
| `apache_conf` | `C:\Program Files\Apache Software Foundation\*\conf` |
| `programdata_ssl` | `C:\ProgramData\ssl` |
| `openssl` | `C:\OpenSSL*` |

Add your own folders with the adapter setting `windows_extra_roots` (comma-separated, at most 10; `adapter pack --windows-extra-roots` for the pack files). Each must be an absolute folder with plain names. Drive roots (`C:\`), whole profiles (`C:\Users\<name>`), the Windows, Program Files and ProgramData trees, and private-key folders (`.ssh`, `.gnupg`, `Crypto`, `SystemCertificates`, `Protect`, `Credentials`, `Vault`, `MachineKeys`) are refused. Extra roots are named `extra1`, `extra2`, ... in order.

Each root has its own keystore query (`meiscope_keystores_windows_<root>`) and counts query (`meiscope_keystore_counts_windows_<root>`). Every run reports, per root, `root.<id>.files_seen`, `root.<id>.skipped_oversize`, `root.<id>.skipped_excluded` and `root.<id>.skipped_limit`; `keystore_max_files` applies to each root. Elapsed time per root is in osquery's own `osquery_schedule` table (`wall_time_ms` per query), and the Windows CI job reports it for every root with a 180 s limit per query.

## The feature flag

The core's current contract (0.4.1 and 0.8.0) rejects unknown fields, so it
rejects store and file targets and adapter evidence. Until the core adopts
the proposal (`api/proposed/collector-0.5.0-proposed.yaml`), the osquery
adapter keeps all of it behind `MEISCOPE_FEATURE_LOCAL_STORE_V1`, which is
**off by default**. With it off the adapter emits nothing, logs and counts
what it skipped (`skipped_feature_disabled`) and does not advance its cursor,
so nothing is lost when the flag is turned on. Turn it on only after the core
has adopted the contract.

## Deployment

### Fleet

1. `fleetctl apply -f packs/osquery/fleet-queries.yml` (or per team).
2. Create an API-only user with the observer role and a token; store the token
   with `meiscope-collector credential set fleet_api_token`.
3. Collector config:
   ```json
   [{"name": "fleet", "adapter": "osquery",
     "settings": {"mode": "fleet", "url": "https://fleet.example.test", "team_id": "2"},
     "credentials": {"api_token": "fleet_api_token"}}]
   ```
   The adapter lists the saved queries (`GET /api/v1/fleet/reports`, falling
   back to `/api/v1/fleet/queries` on a Fleet that lacks it; Fleet 4.93
   deprecates the latter), reads each pack query's report
   (`.../{id}/report`) at most 5 requests per second, and ingests rows newer
   than the stored `last_fetched` per host. It needs a Fleet that offers
   saved-query reports (4.4x and later); an older Fleet gets a clear error.
   Verified against Fleet 4.93.2 (`task test:integration`).

### Kolide and other pipelines (log sink)

Add `packs/osquery/meiscope.conf` to the pack configuration. Send results to
the collector host, either:

- **JSONL directory**: point osquery's filesystem logger (or your Fluent Bit /
  Logstash output) at a directory the collector can read; config
  `{"mode": "logsink", "dir": "/var/log/osquery"}`. Complete new lines of
  `*.log`, `*.json`, `*.jsonl` are read in name order; log rotation is followed.
  Of several snapshots in one run only the latest per host and query is mapped.
- **HTTP push**: the optional receiver (`meiscope-collector receiver run`, off
  by default, loopback or private address only, bearer token, 1 MiB limit,
  rate limit) spools pushed events into that directory. See docs/install.md.

### Standalone (direct)

Run each query of the pack with `osqueryi --json "<sql>"` (print a query with
`meiscope-collector adapter pack --query NAME`) and save the output as a file
whose name ends with the query name, then
`{"mode": "direct", "host": "web01.example.test", "files": "a.json,b.json"}`.
`observed_at` is the collector's clock because `osqueryi` records no time.
Unchanged files are not read again.

## Result mapping

| Row | Observation |
|---|---|
| certificate | target `store` (`posix/system` or `windows/<location>[/<sid>]/<store>`) with the file path when osquery reports one, outcome `cert_seen`, `adapter.certificate` (SHA-1 and metadata), `custody.key_custody: unknown` |
| keystore file | target `file`, outcome `reached`, `adapter.file` (SHA-256, size, mtime, owner, mode, store type) and, for keystore containers, the finding `keystore_not_parsed` |

All with `method: adapter`, `adapter.source: osquery`.
