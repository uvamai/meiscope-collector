# meiscope-collector v0.4.0

## Re-install required: older collectors can't enrol with the new codes

Enrolment codes issued from the Meiscope portal are now tied to one approved
collector request: its collector name, device type (deb, rpm or container) and
architecture. Collector versions before v0.4.0, including `v0.3.0-rc1`, don't
send those details, so **they can't enrol with these codes**. To enrol a new
collector, install v0.4.0 and request a new code in the portal. A collector
that is already enrolled keeps running; renewal and scope delivery don't change.

## What is new since v0.3.0-rc1

- **`enrol` says what it is.** The enrolment request now carries the collector
  name (`MEISCOPE_COLLECTOR_NAME` or `--name`) and what the binary was built for:
  operating system, architecture, package type and version. If they differ from
  the approved request, the core refuses with a generic message and the code
  stays usable; the portal shows the tenant admin the reason. A binary built by
  hand, without a package type, can't enrol.
- **Only the Meiscope CA is trusted at enrolment.** `MEISCOPE_CA_BUNDLE`
  (the CA certificate you save from the portal) is now **required**, and it is
  the only CA the first contact trusts: the system roots are not. If the core's
  certificate does not come from that CA, the collector stops before it sends
  the code.
- **No redirects at enrolment.** If the core's address answers with a
  redirect (any 3xx), the collector stops with an error and does not send the
  code anywhere else.
- **Token file checks.** `enrol --token-file` refuses a file that group or
  others can read (use mode 0600; the install steps already do). After a
  successful enrolment, the collector overwrites the file with zeros and
  deletes it. If enrolment fails, the file is kept so the code can be used
  again.

## What you need to change

- Set `MEISCOPE_COLLECTOR_NAME` to the name you approved in the portal.
- Keep `MEISCOPE_CA_BUNDLE` pointing at the CA certificate from the portal.
- Re-install from the v0.4.0 packages, then request and use a new code.

## Known limits

- The Windows binary is not Authenticode-signed, and the enrolment steps are
  for Linux.
- The wipe overwrites the file in place; on a copy-on-write or journaled
  filesystem or a snapshot, old blocks may remain. Keep the code file in a
  directory only root can read, as the install steps do.
