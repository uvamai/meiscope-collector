**Pre-release.** `v0.3.0-rc1` is a release candidate for the first customer
installs. It is not marked "Latest"; `v0.2.0` stays the latest release until
`v0.3.0`.

## What is new since v0.2.0

- **Enrolment** (`meiscope-collector enrol --token-file`): the collector
  creates its private key on the host and sends only a certificate request.
  It gets a client certificate for mTLS and pins the core's CA and
  scope-signing keys. The one-time code is read from a file or standard
  input, and is never printed or logged.
- **Enrolled runtime** (`meiscope-collector run`): talks to the core over
  mTLS only. It renews its certificate, fetches and verifies the signed
  scopes, polls Certificate Transparency for the owned domains, and reports
  its state on `GET /status`.
- **Probing the signed scopes**: an enrolled collector probes exactly the
  explicit targets in the signed scopes it holds, under the ScanPolicy. Pacing
  now waits outside the connection timeout (S-25).
- **Adapters**: Azure Key Vault, App Gateway, App Service, Entra and Defender.
- **Container image** `ghcr.io/uvamai/meiscope-collector`, cosign-signed by
  digest, with a CycloneDX SBOM attestation.

## Install

See **Install on Linux** in the README. In short: download the `.deb`,
`SHA256SUMS` and the `.sigstore.json` bundle, run `sha256sum -c` and
`cosign verify-blob`, install, save the CA certificate and the enrolment
code from the portal, enrol, then start the service.

## Known limits

- The ScanPolicy pacer property tests are not written yet (issue #13). That
  check shows as skipped.
- The Windows binary is not Authenticode-signed.
- Packages are attached to this release only. There is no signed apt or yum
  repository yet.
